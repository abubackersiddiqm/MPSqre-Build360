# MPSqre Build360 v0.3.3

## Migration index-name compatibility hotfix

Django validates explicit database index names against a 30-character portable
limit. Phase 3 included three names longer than that limit, causing
`models.E034` before migrations could run.

This release shortens the names in both the runtime models and their matching
initial migrations:

- `configuration_active_lookup_idx` -> `cfg_active_lookup_idx`
- `subscription_company_active_idx` -> `sub_company_active_idx`
- `subscription_override_lookup_idx` -> `sub_override_lookup_idx`

No fields, constraints, query semantics, tenant boundaries, or business behavior
change. The affected Phase 3 initial migrations had not executed because Django
failed during the pre-migration system check.
