# MPSqre Build360 v0.15.2

## Purpose

Cumulative Phase 15 backend consistency and installer-compatibility hotfix.

## Changes

- Accepts a locally generated and already-applied `vendor.0002` migration when it is semantically limited to removing and recreating `supply_stage_range_valid`.
- Ignores harmless Django migration-writer differences such as quote style, whitespace and `Q` clause ordering.
- Rejects unexpected migration operations before changing any source file.
- Normalizes the accepted migration source to a deterministic canonical copy for future versioned baselines.
- Replaces floating-point serializer `min_value` values with exact `Decimal` instances.
- Updates backend and frontend release metadata to `0.15.2`.

## Database impact

No new database operation is introduced beyond `vendor.0002`. When that migration is already recorded as applied, Django reports `No migrations to apply`.
