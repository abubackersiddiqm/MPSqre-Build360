# MPSqre Build360 0.3.4

## Local authentication routing hotfix

This release fixes host-based Next.js development at `http://localhost:3000`.
Next.js does not automatically load the project-root `.env` when its working
folder is `frontend`, and the Docker-only hostname `api` is not resolvable from
a host Node process. The server-side authentication proxy therefore could fail
before credentials reached Django.

Changes:

- resolves the Django API to `http://127.0.0.1:8000/api/v1` in non-production
  when `INTERNAL_API_BASE_URL` is absent;
- maps an accidentally inherited Docker URL such as `http://api:8000/api/v1`
  to localhost during host-based `next dev` execution;
- still uses the Docker service hostname in production containers and fails
  closed when the production internal API URL is absent;
- adds `frontend/.env.example` for the host-development routing contract;
- adds a local frontend setup utility that creates `frontend/.env.local`;
- returns actionable, non-sensitive authentication errors;
- adds tests for explicit, Docker-hostname mapping, local fallback, and
  production URL resolution.

No database migration or backend business logic is changed.
